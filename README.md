# Reproduce the calculations

## Setup and run

Use Python 3.12. The tested versions are listed in `requirements.txt`.

```bash
python -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python run.py
```

On Windows, activate with `.venv\Scripts\activate`. All paths are resolved relative to the scripts; no network access is used after installation. Results and generated figures are written to `results/`. Running the complete workflow takes several minutes, depending on hardware.

Run the parts separately with `python run.py field` or `python run.py junction`. Running both, in either order, also produces the combined diagnostic figures.

## What is reproduced

- **Field analyses:** censored waiting-time fits and trajectory-bootstrap uncertainty; preparation-dependent risks; neutral-mode checks; physical coordinates; grouped prediction and parameter tests; spatial/time-resolution statistics. Inputs in `data/` are saved field states, reference waves, spectral arrays and event-level records. Only spectral-vector columns used by the analyses and the six external wave speeds are retained. These are required scientific inputs.
- **Junction calculations:** 1024 trajectories per capture batch, steps 0.01 and 0.005, seeds 2026101501/1502, horizon 1500; noise-off continuation to 300 with DOP853 and two RK4 steps; threshold verification by backward separatrix integration. Bias is 0.15, damping 0.20 and temperature 0.35. All junction inputs are regenerated by code.
- **Noise-on comparison:** reuse the captured states, preserve the generator, compare retained and reset velocity with shared future noise within each pair and independent noise between pairs; seeds 2026101503/1504. Follow-up horizons are 1, 2, 5, 10 and 20. Steps 0.005 and 0.0025 have coupled OU innovations. Ten fixed comparisons use simultaneous one-sided 95% sampling bounds.

Field input files are copied into `results/field_data/` before analysis; the supplied inputs remain unchanged. The field route reanalyses archived simulation output. It does not regenerate all long PDE simulations, spectra or deterministic follow-up trajectories from scratch.

## Outputs and figure mapping

| Calculation | Output in `results/` |
|---|---|
| Waiting-time fits | `field_data/survival_models.json`, `survival_uncertainty.json` |
| Field risk comparisons | `field_data/preparation_risks.json` |
| Grouped prediction | `field_data/grouped_validation.json` |
| Parameter and resolution tests | `field_data/parameter_robustness_analysis.json`, `stochastic_convergence_analysis.json` |
| Noise-off junction experiment | `junction/results.json`, capture NPZ files |
| Noise-on junction experiment | `junction/noise_on_results.json`, first-crossing NPZ files |
| Main figures 3–7 | `figures/long_switch_off_audit`, `finite_noise_history`, `speed_intuition`, `josephson_intervention`, `noise_on_diagnostic` |
| Supplementary figures 1–5 | `figures/exact_spectrum_phase_modes`, `left_truncation_audit`, `physical_predictor_comparison`, `reduced_closure_robustness`, `stochastic_convergence` |

Figure names above omit their image extensions. The initial overview and space-time example (main figures 1–2) are not regenerated by this cached field route. Included arrays support the field statistical and coordinate analyses, not arbitrary new analyses of full noisy trajectories.

The first-capture field sample has 44 episodes in 21 generating trajectories; repeated captures total 126. Validation keeps generating trajectories grouped. A captured branch's noise-off outcome is not a noisy committor. Terminal retained episodes are censored; each risk horizon has its own complete-follow-up cohort. Do not treat these cohorts as one survival curve.

Junction continuation fractions condition on capture before time 1500. Uncaptured paths are not failed continuations. Noisy crossing events are detected on finite integration grids. Sampling confidence bounds do not certify continuous-time numerical accuracy or a complete reduced Markov model.

## Apply the risk-gap diagnostic to other data

```bash
python code/preparation_gap.py pairs.csv --family-size 1
```

The CSV must have columns `outcome_a,outcome_b`, with binary values and one independent paired unit per row. The default is a two-sided absolute-gap bound. Add `--directed` only for a contrast fixed before inspecting outcomes; use the total number of planned comparisons as `--family-size`. Repeated correlated observations cannot be treated as independent rows. Both preparations must share the visible label, subsequent dynamics, event definition and observation rule. A positive half-gap lower bound excludes a common prediction at a smaller chosen error tolerance. A small lower bound is inconclusive.
